# DECISION: project-shipped manifest (Phase 1) отложен

Статус: принято. Дата: 2026-10-06.

## Решение

Полный редизайн «проект поставляет `devbox.capabilities.json` + host-ceiling +
`reconcile` + `probe`» не внедряется сейчас. Вместо него — generic-порт-политика и
host-side проверки (Wave 1.5).

## Почему

На момент решения: два активных проекта (Muffin, MidasAI) и один подтверждённый
инцидент дрейфа — профиль Muffin указывал на порты 8765/8080 вместо реальных 47xxx
супервизора. Один инцидент закрывается регресс-тестом и проверкой в `doctor`, а не
новым протоколом.

## Что сделано вместо

- `port_ranges` + `port_deny` (валидация R27–R33): любой сервис в диапазоне виден
  агенту без per-project правок; вне диапазона — 403.
- Ingress переписывает `<base href>` → `/p/<port>/` для length-framed HTML без gzip,
  поэтому Flutter web (уважающий `<base>`) работает под префиксом без `--base-href`.
- `devbox allow` ре-валидирует профиль после правки и отклоняет порт моста и
  host-сервисы без своей авторизации.
- `doctor` ловит дрейф профиль↔`tools/*/registry.json`, проверяет живость runner и
  `ui_port`, делает WARN-only реверс-скан loopback-портов.
- `runner_commands` Muffin: `start_infra`, `staging_status`, `staging_logs`.

## Evidence-gate (что разблокирует Phase 1)

Внедрять manifest и `reconcile`/`probe`, если выполнено хотя бы одно:

- ≥3 активных проекта упираются в один структурный предел (не дрейф), либо
- ≥2 независимых инцидента дрейфа профиль↔реальность за релизный цикл, либо
- онбординг проекта внешним владельцем, который не может править host-профиль.

До этого generic-порт-политики и `doctor` достаточно.
