# ARENA_TASK.md — шаблон ТЗ для агента

> Скопируй в корень проекта как `ARENA_TASK.md` (в контейнере это
> `/workspace/ARENA_TASK.md`) и заполни. Агент читает этот файл первым, до
> любого плана. Незаполненные места — повод спросить, а не выдумывать.

## Цель

Что должно получиться в итоге, одним абзацем. Без «улучшить всё».

## Scope

- Что входит в задачу (файлы, модули, поведение).
- Что явно **не** входит.

## Критерии приёмки

- [ ] Наблюдаемый результат 1 (какая команда/запрос → что ожидается).
- [ ] Наблюдаемый результат 2.
- [ ] Регрессия: что должно продолжать работать.

## Процедура проверки

Точные команды на девбоксе (через мост), например:

```bash
./gradlew test --tests 'com.example.SomeTest'
flutter analyze && flutter test
```

Как проверить UI (если нужно): какой сервер поднять, какой порт/URL, что снять.

## Что не трогать

- Секреты и `.env` (не читать и не печатать).
- Не относящиеся к задаче файлы (реформат, переименования вне scope).
- Публикация/теги/force-push — только с явного согласия.

## Отчёт

Как агент должен отчитаться: `git diff`, результаты тестов, скриншоты,
явные отступления от ТЗ.
