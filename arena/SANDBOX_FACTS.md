# SANDBOX_FACTS — замерено зондом 2026-09-11, не по памяти

## Характеристики песочницы арена-агента

| Параметр | Значение (замерено) |
|---|---|
| ОС | Debian 13 (trixie), ядро 6.1.158+, x86_64 |
| CPU / RAM / диск | 2 ядра / 1.9 ГиБ (свободно ~1.5) / 25 ГБ (свободно 20) |
| Права | **root (uid=0)**, sudo без пароля, apt-get есть |
| Python / Node / git | 3.13.14 / 20.20.2 / 2.47.3 |
| Java | OpenJDK 11 (javac есть). Для Spring Boot 3 (нужна 17+) локально НЕ хватит |
| Компиляторы | gcc, make — есть |
| Docker / podman | **нет** (и не проверялось, что демон поднимется — скорее всего нет привилегий) |
| GUI / DISPLAY | нет |
| Браузер | изначально нет; **playwright + chromium поставил за ~2 мин** (нужны `--no-sandbox --disable-dev-shm-usage`), скриншоты работают |
| Сеть | исходящая открыта на любые порты (проверено: 22, 25, 443, 3389); DNS по именам; pypi/github/npm = 200 |
| Персистентность | сохраняются только файлы под `/home/user`. `~/.cache`, `~/.local`, `/usr/local/site-packages` **не сохраняются** → playwright/браузер в новой сессии ставится заново (~2-3 мин) |
| Права на файлы | исполняемый бит теряется после снапшота (замечено на ./mcp) — chmod при старте сессии |
| Лимиты bash | stdin закрыт, нет TTY; timeout по умолчанию 30 с, максимум 1800 с |
| Серверы | стартуют через start_process; порты 0.0.0.0 видны как live-preview `https://{port}-{id}.e2b.app` |

## Мои инструменты (сторона арены)

| Инструмент | Доступ |
|---|---|
| `bash` | шелл песочницы, cwd=/home/user; root; любая установка пакетов |
| `start_process` / `get_process_output` / `stop_process` | фоновые процессы/серверы, жду порты и логи |
| `read_file` / `write_file` / `edit_file` | файлы workspace; **read_file видит изображения** (PNG я реально смотрю) |
| `present_file` | показать файл тебе |
| `web_search` / `fetch_page` / `image_search` | исходящий интернет, документация, картинки |
| `generate_image` / `generate_speech` / `add_voice` | генерация изображений и речи |
| `ask_user` | задать тебе вопрос с вариантами |
| `mcp_client.py` + `./mcp` | вызов инструментов ТВОЕГО компа через туннель |

## Инструменты на твоём компе (после подключения, по README моста)

| Тул | Доступ | Требует разрешения |
|---|---|---|
| `read`, `glob`, `grep`, `todowrite` | только папка PROJECT_DIR | нет |
| `lsp` (hover/findReferences) | jdtls для .java, dart для .dart | нет |
| `write`, `edit`, `apply_patch` | только папка PROJECT_DIR | да (джоб awaiting_permission) |
| `bash` | шелл ВНУТРИ контейнера: JDK 21, Flutter/Dart, git; cwd=корень проекта | да |
| `webfetch` | исходящая сеть из контейнера | да |

Вне корня проекта мост **отвергает** операции, а не спрашивает. Ключи, docker.sock,
домашняя папка и облачные креды в контейнер не монтируются (SECURITY.md).

## Где я раньше был неправ (зафиксировано)

1. «Скриншоты возможны только если добавить Chrome в твой образ» — **неверно**.
   Браузер ставится у меня; скриншот проверен (probe-headless-shell.png).
   Правильная схема для «где экраны кривят»: пробросить порт Flutter-web/widgetbook
   наружу (именованный туннель со второй hostname) и снимать его из моей песочницы.
2. «В песочнице нет прав ставить софт» — не утверждал, но молча подразумевал.
   Замерено: root + sudo без пароля + apt.
3. «В песочнице есть Java» — раньше не знал; теперь факт: только 11, не 21.
