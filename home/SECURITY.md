# Безопасность

Ты публикуешь наружу инструменты, которые могут **читать файлы, выполнять команды
и править код** на твоей личной машине. Это эквивалент удалённого shell-доступа.
Относись соответственно.

## Обязательный минимум

| Мера | Зачем |
|---|---|
| **Bearer-токен** на эндпоинте | Без него туннель — это открытый shell в интернете. Токен длинный, случайный, не в git. |
| **Permission mode = `safe`** | Файловые тулы работают, сетевые/разрушительные команды требуют явного разрешения. |
| **Один корень workspace** | Монтируй только конкретный проект, не `C:\Users\you` и не весь диск. |
| **Только исходящий туннель** | cloudflared соединяется наружу, входящие порты не открываются, роутер не трогаем. |
| **Никаких секретов в монтируемой папке** | `.env`, ключи, `auth.json` — вне `/workspace` или в `.dockerignore`. |
| **Откат через git** | Каждая правка должна быть видна в `git diff` и откатываема. |

## Что НЕЛЬЗЯ монтировать в контейнеры

- Docker-сокет (`/var/run/docker.sock`) — это фактически root на хосте.
- Домашнюю директорию целиком.
- Личный SSH-агент / `~/.ssh`.
- Облачные креды (`~/.aws`, `~/.config/gcloud`, `~/.kube`).
- Производственные секреты и токены.

## Про уровень изоляции

Контейнеры делят ядро хостовой ОС. Permission-режимы ограничивают **список
инструментов**, но не являются границей безопасности против скомпрометированной
сессии или промпт-инъекции (например, через страницу, которую агент скачал).

Если нужна настоящая изоляция — запускай исполнительную часть в отдельной ВМ
(gVisor / Kata / Firecracker) или на отдельной машине, а туннель веди к ней, а не
к основной системе.

## Компромисс, который стоит принять осознанно

Ты сознательно открываешь доступ к своей среде разработки, чтобы получить
качественные правки без ограничений песочницы. Это разумно при условиях:

1. токен + `safe`-режим включены;
2. смонтирован только проект, а не система;
3. работа идёт в git-ветке/worktree, откуда всегда можно откатиться;
4. ты видишь логи (`docker compose logs -f`) и можешь остановить стек одной
   командой: `docker compose down`.

## Гигиена на будущее

- Токен — отдельный, не переиспользуй пароли/ключи.
- Ротация токена — просто правка `.env` + `docker compose up -d`.
- `VLESS_SUB_URL` — секрет того же уровня: по URL подписки кто угодно поедет
  на твоём трафике. Не коммитить, не публиковать, в `.env` он уже под
  gitignore.
- Всё, что выставляется наружу, должно быть остановлено, когда не используется:
  `docker compose stop cloudflared`.
